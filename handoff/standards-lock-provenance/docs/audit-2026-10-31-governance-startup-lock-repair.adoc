== Verdict in one paragraph

A caller pinned to `metadatastician/standards` at `fad242d`
(+fad242d35291de1898242d6737ba02b74a59a2f2+) is _not_ startup-valid, and no lock-only repair can
make it so: the commit is immutable, and a repair commit on a side branch is not callable, because
GitHub resolves a called reusable workflow only at a commit reachable from the callee's default
branch. The record is *already repaired on `main`* (f335165 for nine leaf records, cf8f912 for the
rest) — this change adds the guard, the measurements and the migration order, not a second fix.
Every startup-valid commit is at least 452 commits of policy change away from the broken baseline,
so "minimal repin" and "policy-neutral repin" both misdescribe what a consumer must do.

== Mechanism

* GitHub validates the *callee* against the callee repository's own
  `.github/workflows/actions.lock` **as it exists at the pinned commit**.
* A **leaf** dependency record (an action) must name the reviewed tag/branch in `ref:`; a record
  whose `ref:` repeats its own 40-hex pin is rejected at *Set up job*. The pin stays in the record
  key and in `commit: sha1-<40 hex>`.
* A **reusable-workflow** record (callee `owner/repo/.github/workflows/x.yml@<ref>`) pins by SHA:
  its `ref:` *is* the pin, plus the union of the callee's external `uses:` under `uses:`.
* Keys stay SHA-shaped; `relock-sha-keys.sh` re-keys tag-spelled entries and the tag goes in `ref:`.

== Source-resolution expression audit

`${{ job.workflow_sha }}` *— supported, used correctly.* 15 checkout sites in
`governance-reusable.yml` (workflow-staleness, uuid-v7/v8-conformance, allowlist-preflight,
actions-policy-live, validate-hypatia-baseline, package-policy, quality, actions-lock-verify,
trusted-base, licence-consistency, exemption-ratchet, debt-ratchet, js-runtimes-provision,
js-runtimes). Available only inside a called reusable workflow, where it is the *callee's* commit.
It is not `github.workflow_sha` (the caller's), and not `github.job_workflow_sha`, which does not
exist. It is unavailable on GitHub Enterprise Server. Nothing here needs changing.

`ref: main` *— one remaining floating helper checkout.* `changelog-reusable.yml:126` checks out
`metadatastician/standards@main` to read the canonical `cliff.toml`. It is data, not executed code,
but it is the only floating ref left in the reusables. Recommended as a separate PR (consumer-visible,
needs its own canary): `ref: ${{ job.workflow_sha }}`. *Not changed here.*

Hypatia HEAD clones *— pinned by input, HEAD opt-in.* `hypatia-ref` (default `adb2f41d…`),
`panic-ref` (`410a8f82…`), `pons-ref` (`bca1ea28…`); anything not 40-hex is rejected, and
`git ls-remote … HEAD` runs only when a caller explicitly passes `HEAD`. The clone is
`fetch --depth 1 origin "$SHA"` plus a `rev-parse` assertion, so the resolved commit builds and keys
the cache. Residual: `HEAD` remains a supported input for canary callers.

Reusable-dep refs *— one drift, advisory.* `--remote` on `main` reports exactly one:
`hyperpolymath/cicd-squabbler@1ab1507a… ref: main` now resolves to `193349090e…`. Drift is measured
*not* to be startup-fatal (`333b06a` records `dtolnay/rust-toolchain@e2a55d2f… ref: v1`; `v1` now
resolves to `683b588c…`, and hypatia's jobs at that pin start and run).

== The repair in this change

* `scripts/check-lock-pin-provenance.sh` — representation + provenance: leaf `ref:` must name a
  tag/branch, reusable records may pin by SHA, `commit:` must be `sha1-<lower hex>` agreeing with a
  SHA-shaped key, tag-keyed records must record their own key. `--remote` resolves refs with
  `git ls-remote` (drift advisory, unresolvable ref fatal, unreadable remote `UNVERIFIED`).
  Exit 2 whenever inspection did not happen.
* `scripts/tests/check-lock-pin-provenance-test.sh` — 18 fixture cases, including the exact
  `fad242d` and `1725beb` record shapes.
* `.github/workflows/lock-selfcheck.yml` — one extra step, same job and check name, so the required
  context `Lockfile self-consistency` also covers records no workflow uses.
* This document.

Deliberately not done: no change to `check-actions-lock-gate.sh`, no new required context, no
allow-list widening, no de-pinning, no job disabled.

== Consumer migration — the canary protocol

A *canary* here means one small workflow, in the consumer repository, that calls the shared
governance reusable at exactly the candidate commit and does nothing else, so the run answers one
question: **does runner setup accept this source pin from this repository?** It is not a policy test;
it is the check that must pass before a policy test can happen.

. *Verify the source* (git objects only, no writes):
  `bash scripts/check-lock-pin-provenance.sh .github/workflows/actions.lock` → exit 0;
  `bash scripts/check-lock-sync.sh .github/workflows` → in sync;
  `bash scripts/close-lock.sh --check .github/workflows/actions.lock` → closed;
  `bash scripts/lock-selfcheck.sh <sha>` → SELF-CONSISTENT (needs mikefarah yq v4).
. *Confirm reachability* — the SHA must be an ancestor of the callee default branch. Existence is not
  reachability, and a branch-tip repair commit is never callable.
. *Canary one consumer:* a workflow whose only job is
  `uses: metadatastician/standards/.github/workflows/governance-reusable.yml@<candidate>` on a
  scratch branch. **Pass = the run has jobs.** Zero jobs or `startup_failure` = stop, do not repin.
. *Enumerate a known-good control* in the same run: a second canary at a pin that already executes
  somewhere (e.g. `333b06a` in hypatia). If the control also returns zero jobs, the blocker is the
  consumer, not the source.
. *Acknowledge the policy delta*, then repin `uses:`.
. *Re-verify:* every expected job present, `Actions lockfile verify` green, required contexts reporting.

== Rollback

*Consumer:* restore the previous `uses:` pin and push. If that pin is the broken one, governance
reports _zero jobs_ and no required context arrives — a rollback to `fad242d` does not restore a gate,
it removes one. To stay gated during a rollback, pin the last known-good SHA and re-run the canary.

*Standards:* additive — one script, one test, one step, one document. Revert the merge; the required
context name is unchanged, so no branch-protection surgery is needed.

== Limits of this measurement

* `gh actions-lock --verify-local` could not be run: the extension install fails downloading its
  release asset (EOF). The three repo-owned checks above were run instead.
* Mikefarah `yq` v4 is absent, so `lock-selfcheck.sh` was exercised as its three components.
* Repository Administration settings are unreadable (`403`), the same blocker recorded in 8d1a2aa.
* A consumer canary in `hyperpolymath/cyo` returned zero jobs for *every* pin tried, including
  `333b06a`, which runs in hypatia today — a caller-side blocker in `cyo`, independent of this
  defect and not diagnosable from here.
* `hyperpolymath/cicd-squabbler@… ref: main` drift and `changelog-reusable.yml:126 ref: main` are
  recorded as findings, not changed.

* *Hypatia:* on `333b06a` and executing policy — the live evidence for that pin, and the natural first

* *gitbot-fleet / burble:* same matrix, canary in-repo before moving the pin.
